# CampusOne 真人演示视频录制指南

## 推荐成片结构

目标时长为 4 分 10 秒至 4 分 30 秒，给赛事 3–5 分钟限制留出余量。视频围绕一次完整申请和一次 AI 故障处理展开，可以全程使用产品画面。团队信息以片头字幕呈现；如有需要，仅选用项目简介 PPT 中的 1–2 页，并计入总时长。

团队信息：厦门大学；胡博（队长）、温广琛、许佳锋；指导教师：张盈谦。统一来源为 `competition.config.json`。以下为录制节奏参考，逐段讲解以《CampusOne_3-5分钟演示视频脚本.md》为准。

| 时间        | 画面与操作                      | 真人讲解重点                                               |
| --------- | -------------------------- | ---------------------------------------------------- |
| 0:00–0:20 | 产品首页叠加项目与团队字幕 | 项目名称、厦门大学团队、高校场地申请场景 |
| 0:20–0:40 | 产品首页总览                     | 场地申请场景、学生端与审核端、默认模拟数据                                |
| 0:40–1:05 | 点击重置演示；进入学生申请              | 一键复现、无需 API Key、数据均为模拟数据 |
| 1:05–1:30 | 填写描述并调用表单助手；故意设置超容量人数，执行预检 | AI 只整理表达；CAP-001 等确定性规则负责判定                          |
| 1:30–1:50 | 修正人数，重新预检并由学生确认提交          | AI 不自动保存、不代替用户提交                                     |
| 1:50–2:20 | 切换审核人；生成审核摘要；人工填写退回原因并退回   | 摘要只排列已验证证据，退回是人工动作                                   |
| 2:20–2:50 | 切回学生；创建 V2，修改后再次提交         | V1 不被覆盖，V2 与退回理由可追溯                                  |
| 2:50–3:15 | 审核人再次审核、批准并办结              | 状态机限制权限和顺序，重复操作具有幂等性                                 |
| 3:15–3:40 | 展开版本、事件时间轴、规则证据和 AI 运行记录   | 每个结论都能回到角色、版本、规则和模型运行                                |
| 3:40–4:05 | 注入“虚假规则”或“非 JSON”故障        | AI 结果被拒绝或降级，正式事务状态保持不变                               |
| 4:05–4:25 | 回到产品总览或保留运行证据画面 | 当前完成范围、下一步真实用户试点 |

## 录制前准备

1. 参赛单位、成员和指导教师已记录在 `competition.config.json`，录制时直接核对。联系邮箱仍待填写；旧 Word 材料需在提交前据此重建。项目简介 PPT 使用 v3。
2. 使用 1920×1080 屏幕，浏览器缩放设为 100%；关闭通知、聊天软件弹窗和自动填充提示。
3. 优先录制本地产品 `http://localhost:3000`，避免私有部署登录页出现在视频中。录制前运行 `npm run dev`，确认页面和一键重置正常。
4. 不打开终端、`.env.local`、部署设置或任何包含 API Key 的页面。默认 `LLM_MODE=mock` 足以完成稳定演示。
5. 提前走两遍完整点击路径。确认故障注入时对应 AI 任务仍可调用；如果办结后受状态限制，将故障段安排在批准前。第二遍开始计时，把每次点击和讲解句子写在纸上或副屏提示器中。
6. 麦克风距离嘴部约一拳，选择安静房间；先录 15 秒样音，检查爆音、底噪和音量。

## 推荐录制方式

使用任一支持“屏幕 + 麦克风”的工具即可，例如 OBS、PowerPoint 屏幕录制或系统自带录屏。推荐一次连续录完实机段，再剪掉开头结尾的空白；不要依赖大量跳剪掩盖无法运行的操作。

- 画布：1920×1080，横屏 16:9。
- 帧率：30 fps。
- 输出：MP4，H.264 视频 + AAC 音频。
- 声音：人声清楚优先，背景音乐可不加；若添加，音量必须明显低于人声。
- 文件名建议：`CampusOne_3-5分钟真人演示视频.mp4`。

## 讲解原则

- 先说业务动作，再说技术证据。例如“人数超容量被规则拦截”，不要先讲框架名称。
- 明确区分 AI 建议、程序规则和人工决定，避免说成“AI 自动审批”。
- 如需提及测试，引用当前项目报告记录的 78 个自动化用例和 9 个真实模型故障组合；真实用户试点尚未完成，不宣称效率提升百分比。
- 遇到页面响应稍慢可以自然等待，不要反复点击导致重复操作。
- 如果说错一句，停两秒后从上一句重说，后期更容易剪辑。

## 导出后必查

- 总时长严格在 3:00–5:00 之间，建议不超过 4:30。
- 从头到尾完整观看一次，确认文字可读、光标可见、讲解与画面同步。
- 片头的单位、成员、指导教师与 Word、PPT 完全一致。
- 视频确实展示退回、V2、批准办结和一次安全降级，而不只是口头描述。
- 画面中没有 API Key、密码、真实学生信息、浏览器书签或无关通知。
- 在另一台设备上试播，确认声音正常，再按赛事系统限制检查文件大小。
