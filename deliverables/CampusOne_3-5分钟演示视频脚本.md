核对方式：查看实际申请页面及可访问元素，核对四个视图的源码，并以独立 HTTP 演示会话验证按钮对应的完整状态流程。未完成整条路径的浏览器逐键点击验收。此次正常表单整理、审核摘要及虚构规则故障均使用 `LIVE / deepseek-chat`；录制时以你当次页面显示为准。

**当前版本注意：`docs/recording-readiness.md` 列出的三项已修复——退回意见现为管理员必填并对申请人可见，退回通知按真实状态与意见起草（八次实测全部通过、无“等待审批”类矛盾表述），事务档案支持选择版本并逐字段对照。第 8、9、11 段已按新流程改写。**

## 一、开录前准备，不计入视频

1. 打开正在运行的本地站点 `http://localhost:3000/#workflow`。本稿按该版本核对；不要录到一半改用线上地址、切换浏览器或刷新页面，这些操作可能切换演示会话或丢失未保存内容。
2. 使用横屏，尽量让网页可用宽度达到 1280 CSS 像素以上，以便左侧导航、中央申请表、右侧“AI 辅助台”同时出现。1920×1080 录屏可作为起点；若右侧辅助台掉到表单下方，先扩大窗口或适当缩小浏览器比例，直到三列可见且文字可读。不要在窄的侧栏里直接开录。
3. 关闭翻译提示和其他浮层。将下方“V2 活动说明”复制到备用文本文件，正式录制时直接粘贴。
4. 点击左侧下方 **重置演示**，再明确点击 **申请人**。进入 **申请办理**，把右侧 **演示模型异常** 选为 **正常输出**。重置数据不会自动恢复身份和故障选项，三项都要核对。
5. 顶栏应为 **草稿 · V1**、**审计 1**、**AI 0**，有 **模拟数据** 标识。以下字段保持默认，避免引入额外规则失败。

| 字段 | 开录前值 |
| --- | --- |
| 活动名称 | 2026 秋季社团招新宣讲会 |
| 申请组织 | 学生创新协会 |
| 候选场地 | 大学生活动中心 · 120 人 |
| 预计人数 | 80 |
| 开始时间 | 2026-09-08 19:00 |
| 结束时间 | 2026-09-08 21:00 |
| 现场负责人 | 林同学 |
| 联系电话 | 13800000000（系统预置演示值） |
| 设备需求 | 投影、无线麦克风、基础扩声 |
| 活动说明 | 面向全校新生介绍协会方向与年度计划，现场包含项目展示、成员分享和招新答疑。 |

日期控件的显示顺序随浏览器语言变化。保留上述预置日期即可；不要临时改成当天日期。演示材料中的场地和联系人均为模拟内容。

先走一遍下面的路径，再按第 4、5 步重新准备。正式录制中的三次 AI 调用为：正常表单整理、虚构规则表单整理、正常审核摘要。不要提前在正式录制会话里运行 AI，否则计数会增加。

## 二、逐镜头操作与口播

时间为成片预算。每一步以“确认画面”为继续条件，不要为了卡秒数在请求尚未结束时点击下一步。真实模型文字会变化，口播只描述已验证的功能，不逐字预言模型回答。若某次等待明显超出预算，可剪去中间等待并标注“等待过程已压缩”，保留点击、加载和真实结果。

### 1｜0:00–0:20　项目与界面

**操作：** 停留在“申请办理”顶部，鼠标依次指向左侧导航、中央申请表和右侧 AI 辅助台。叠加团队字幕。

**确认画面：** 左侧有“申请办理、事务档案、规则与知识、AI 运行证据”四个入口；顶栏为“草稿 · V1”。

**口播：**

> 大家好，我们是厦门大学团队，成员是胡博、温广琛和许佳锋，指导教师是张盈谦。CampusOne 面向高校场地申请。下面通过一份模拟申请，展示规则预检、AI 辅助，以及退回修订到办结的过程。

### 2｜0:20–0:40　规则与材料来源

**操作：** 点击左侧 **规则与知识**。先停在“确定性规则集”，再向下滚动到“场地开放时间与已占用时段”和“场地事务知识库”。最后点击左侧 **申请办理** 回到表单。

**确认画面：** 页面列出 6 条规则、4 份制度；大学生活动中心容量为 120 人，开放时间为 08:00–22:00。材料来源有“模拟”字样。

**口播：**

> 规则与知识页集中展示六条规则、场地条件和四份制度材料。这些都是演示数据。容量、时间和设备由程序核对，AI 使用的知识材料也能在这里找到来源。

### 3｜0:40–1:05　人数超限

**操作：** 把中央表单的 **预计人数** 从 `80` 改为 `180`。向下滚到表单底部，点击 **规则预检**。页面会自动滚向预检结果；等待滚动结束后，将“场地容量充足”这一项放在画面中央。

**确认画面：** 预检显示 **1 项未通过**；规则编号为 **VENUE-CAP-001**，提示 **预计 180 人，超过场地容量 120 人。** 顶栏仍为草稿。

**口播：**

> 先把预计人数改成一百八十人。预检指出人数超过一百二十人的场地容量，同时列出规则编号和判定依据。这个结论由程序直接计算，申请现在还不能提交。

### 4｜1:05–1:20　修正并再次预检

**操作：** 向上滚到 **预计人数**，改回 `80`；再到表单底部点击 **规则预检**。修改字段后，旧的预检结果会清除，必须重新点击。

**确认画面：** **6 项全部通过**。人数为 80，正式状态仍为草稿。

**口播：**

> 把人数修正为八十，再次预检，六项规则全部通过。通过预检后，申请仍处于草稿状态，后续提交和审批需要各自的操作人确认。

### 5｜1:20–1:55　表单建议与人工采用

**操作：** 回到活动说明区域，点击 **让 AI 帮我整理**。右侧 **运行表单整理** 是同一个任务入口，两者只点一个。等待右侧出现“表单整理建议”，向下滚动查看建议下方的知识依据及运行信息，再点击 **人工确认并采用**。

**确认画面：** 建议在点击采用前显示于右侧，运行信息标明 **LIVE / deepseek-chat** 或你实际使用的模式。人数仍为 80，正式状态仍为草稿。完整描述可能无需改写，模型返回原句也属于正常结果。采用后只是更新当前表单，尚未保存或提交。

**口播：**

> 现在请 AI 整理活动说明。右侧显示建议、知识依据，以及本次使用的模型和耗时。申请人检查后点击“人工确认并采用”，建议才进入表单。人数和时间保持原值，正式申请也还没有提交。

### 6｜1:55–2:20　故障输出被拦截

**操作：** 在右侧 **演示模型异常** 下拉框中选择 **虚构规则**，点击 **运行表单整理**。等待结果，拍清错误信息和顶栏“草稿 · V1”。随后把下拉框改回 **正常输出**。此时不要再次调用 AI。

**确认画面：** **输出已拒绝** 和 **RULE_NOT_FOUND**；提示人工继续填写，状态仍为 **草稿 · V1**。关闭故障开关只影响下一次调用，旧的红色结果不会立即消失，属于当前显示行为。

**口播：**

> 接着模拟模型引用虚构规则。校验器返回 RULE_NOT_FOUND，拒绝这次输出，申请仍然是草稿第一版。系统给出继续人工填写的提示。恢复正常输出后，可以继续办理这份申请。

### 7｜2:20–2:45　提交、接件与审核摘要

**操作：** 到中央表单底部点击 **提交申请**，等顶栏变为 **已提交 · V1**。点击左下角 **管理员**，再点击表单底部的 **管理员接件**，等状态变为 **审核中 · V1**。然后点击 **生成审核摘要**，等待右侧结果。左右两处可能有同名入口，只点一次。

**确认画面：** “审核摘要 · 等待管理员判断”，下方列出知识依据及本次模型信息。先接件才能进行后面的退回或批准。

**口播：**

> 申请人确认提交后，切换到管理员并接件。AI 将申请事实和需要人工核对的事项整理成审核摘要，管理员据此判断。这里的身份切换是演示入口，实际接入学校时需要连接统一身份认证。

### 8｜2:45–3:00　人工退回

**操作：** 保持管理员身份，在表单底部 **退回意见** 框内输入：`预计人数接近场地容量上限，请补充现场秩序维护与疏散安排。` 未填写时“退回修改”为禁用状态，可先拍一下禁用效果再输入。填好后点击 **退回修改**；随后点击右侧 **起草退回通知**。

**确认画面：** 顶栏变为 **已退回 · V1**，表单上方出现黄色 **管理员退回意见** 区块并显示刚才那句话。右侧 AI 面板给出“退回通知草稿 · 等待管理员确认”，正文复述同一条意见并要求修改后重新提交，底部有 `LIVE`、模型名与耗时。

**口播：**

> 管理员写下具体的退回意见，这条意见会随退回事件写入后端，申请人能直接看到。AI 起草的退回通知只能引用这条已保存的意见和规则判定，不能自己另编一个理由。

**录制说明：** 退回意见是必填项，服务端也会拒绝空意见的退回请求。AI 草稿仍只是草稿，界面没有“发送”动作，不要说“通知已发送给学生”。

### 9｜3:00–3:30　创建 V2 并补充内容

**操作：** 点击左下角 **申请人**，再点击表单底部 **创建修订 V2**。等顶栏显示 **草稿 · V2**、表单恢复可编辑后，将“活动说明”整段替换为准备好的 V2 文本，其余字段保持不变。点击 **提交申请**；此按钮会重新预检、保存当前表单并提交。

**确认画面：** **已提交 · V2**。切换身份本身不会创建版本；必须先点“创建修订 V2”，然后才能修改。

**口播：**

> 切回申请人，创建修订第二版，再补充现场负责人对入场引导、秩序维护和场地恢复的安排。重新提交时，系统再次检查规则，原来的第一版仍然保留。

### 10｜3:30–3:50　复核、批准、归档

**操作：** 点击左下角 **管理员**，点击 **管理员接件**，等状态成为 **审核中 · V2**。查看补充后的活动说明，点击 **人工批准**；等状态为 **已批准 · V2** 后，再点击 **办结归档**。不用再生成一次审核摘要。

**确认画面：** 顶栏 **已归档 · V2**，表单底部 **流程已完整闭环**。此阶段没有 AI 运行按钮。

**口播：**

> 管理员重新接件，核对补充内容后人工批准，再办理归档。接件、批准和归档是三个明确的动作，服务端会检查操作身份和当前状态。

### 11｜3:50–4:10　版本与事务记录

**操作：** 点击左侧 **事务档案**。拍清右侧“申请版本”中的 **版本 V1、版本 V2** 与 V2 的“当前”标识；左侧“不可变时间轴”上，退回那条事件下方会显示黄色 **退回意见**。向下滚动到 **版本 V2 正文**，拍清右上角“1 个字段有变化”和“活动说明”上的 **已修改** 标记——该字段以删除线显示 V1 原文、箭头后显示 V2 新文。再点一次 **版本 V1**，说明旧版本正文保持原样、查看不会修改任何版本。

**确认画面：** **2 个版本**，正常按本稿仅发生 **9 条状态事件**。界面显示操作角色、前后状态和时间；版本项目前不能点击查看正文，也没有差异对照按钮。

**口播：**

> 事务档案保留两个申请版本，并按发生顺序记录状态变化。退回事件上带着管理员写的具体意见，版本对照能逐字段看出这一版改了什么、改前是什么。旧版本只读，不会被覆盖。

### 12｜4:10–4:30　AI 记录与收尾

**操作：** 点击左侧 **AI 运行证据**。指向运行记录中的任务、模型、耗时和验证结果，特别停留在 **RULE_NOT_FOUND** 所在行。保留此页作为结尾画面。

**确认画面：** 本稿从干净会话开始、未重试时，通常为 **3 次运行、1 次被拒绝**：两次表单整理（一次正常、一次故障），一次审核摘要。真实模型发生重试时，记录数可能增加，以页面为准，不口播固定次数。

**口播：**

> AI 运行证据记录了任务、模型、耗时和验证结果，被拒绝的输出也能查到。本次展示完成了申请、退回修订与归档，并验证了一次模型异常处理。下一步我们将开展真实用户试点，评估填写和审核效率。

## 三、录制时遇到问题，按这里处理

| 现象 | 处理 |
| --- | --- |
| 找不到审核或批准按钮 | 查看顶栏状态与左下角身份。已提交时先切管理员并“管理员接件”，进入审核中才有退回和批准。 |
| 已退回但表单不能修改 | 切申请人，再点“创建修订 V2”；不要直接改锁定的 V1。 |
| 人数改了，旧预检结果消失 | 正常行为，修改后重新点“规则预检”。 |
| AI 结果很长，下方按钮不在画面内 | 向下滚动查看结果末尾；不要再次点击运行。录制前先确认窄窗口下辅助台是否被排到表单下方。 |
| 正常 AI 调用显示错误或拒绝 | 停下这一段，不念成功口播。确认故障选项为“正常输出”后排查；排练重试会增加记录，正式重录前重置。不要把正常调用失败冒充后面的主动故障注入。 |
| 故障段出现其他错误码 | 不念 RULE_NOT_FOUND。先结束这一段并排查，预演确认“虚构规则”确实返回该码后再录。 |
| 关闭故障后仍有红色结果 | 下拉框只控制下次调用，上一条结果仍保留。按脚本继续提交、切换管理员，身份切换会清除当前 AI 展示。 |
| AI 运行次数不是 3 | 检查是否多点了同一任务或发生真实模型重试。记录保留真实情况；需要干净成片时，完成排练后重置并重新开始。 |
| 成片接近 5 分钟 | 压缩导航停留和无内容的等待，保留每次点击、结果、退回修订及最终证据。不要加整套 PPT。 |

## 四、完成后核对

- 总时长在 3–5 分钟，建议 4:20–4:45；当前预算未包含真人实录计时，按你自己的语速排练一次。
- 已录到 180 人超容量、80 人通过、AI 建议人工采用、虚构规则拒绝、V2 和最终归档。
- 没有讲“AI 自动审批”“通知已发送”或“已取得效率提升数据”。版本差异确实可以演示；“通知已发送”仍然不能说，界面只产出草稿。
- 片头团队信息来自 `competition.config.json`，与 PPT 保持一致。
- 全片使用同一版本、同一会话；结果中的模型模式和错误码与旁白一致。
