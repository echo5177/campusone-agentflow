# CampusOne 初赛产品范围

## 一句话定位

CampusOne 场地申请可信智能体：AI 负责理解、整理和解释，程序负责事实与规则，人工负责最终审批。

## 目标用户与痛点

- 学生申请人：不知道填什么、是否符合规则、当前处理到哪里。
- 行政审核人：需要在多个材料和规则之间来回核对，退回意见重复编写。
- 管理者：缺少可追溯的版本、处理时间和模型运行记录。

## 必须实现

1. 固定场地申请表单与脱敏演示数据。
2. `form_assist`：润色已有说明并提示缺项，用户确认后才能采用。
3. 日期、容量、时间冲突、必填字段的确定性预检。
4. 提交、审核、退回、修订 V2、批准的受控状态机。
5. `review_brief`：只整理已验证事实、通过/失败规则和人工判断项。
6. `return_message_draft`：只改写程序已经确定的退回原因。
7. 事务版本、事件时间轴、AI 运行与验证记录。
8. 模型不可用或输出不可信时安全降级，业务仍可继续。
9. 正常、边界、权限、提示注入和模型失败测试。

## 加分项

- 管理员事务总览与每日风险摘要。
- 规则来源与知识片段的可视化证据面板。
- 一键重置演示数据和固定演示剧本。

## 本轮不实现

- 多 Agent 自治协作。
- 真实学校统一身份、OA、教务或支付接入。
- 模型微调、本地 GPU 部署、任意 SQL 和自动审批。
- 通知、缴费、证明申请等第二业务场景。

## 赛事技术选型决策

赛事交流群已明确：不限制使用比赛提供的平台，不限制接入模型，使用自研或开源 Agent 框架不影响评分，重点评价运行效果。因此本项目采用自主开发，不依赖 FastGPT、超星或其他赛方平台。
