# 3–5 分钟演示脚本

## 0:00–0:25 问题与定位

展示 CampusOne 首页：学生不知道规则和进度，管理员重复核对材料；CampusOne 用“AI 辅助 + 程序规则 + 人工决策”形成可信流水线。

## 0:25–1:10 表单与 AI 辅助

学生填写活动说明，调用 AI 整理文案。强调建议等待确认，人数、日期和设备没有被模型改写。

## 1:10–1:45 确定性预检

先演示人数超过容量，程序返回规则 ID、场地容量和申请人数；修正后六项规则全部通过。说明可计算规则不交给大模型。

顺带把镜头给到右侧"开放时间与已占用时段"与"知识库"两张卡片：预检引用的容量、开放时间、已占用时段和制度条文都在页面上，评委可以自己复算。命中的知识条目会标注"本次已引用"。

## 1:45–2:35 提交、退回与 V2

学生确认提交。**用右上角的身份开关切到"管理员"**，并说明这一步是演示专用入口：业务接口只认服务端会话里的身份，请求体里写 `role: "admin"` 不会被采信，生产环境这里换成学校统一身份认证。管理员查看带证据的审核摘要并人工退回；切回"申请人"后生成 V2，V1 和差异仍可查看。

## 2:35–3:15 人工批准与时间轴

管理员批准，展示创建、AI 辅助、预检、提交、退回、修订和批准的完整时间轴。

## 3:15–4:05 故障注入

切换“引用不存在规则”故障，模型输出被拒绝，显示 `RULE_NOT_FOUND`、固定降级文案和未改变的事务状态。

## 4:05–4:35 架构与价值

展示 Agent 运行证据和架构图：模型可替换、业务可扩展，但高风险动作始终在确定性控制面和人工确认之后。
