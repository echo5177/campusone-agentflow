# 技术架构

## 分层

1. **交互层**：学生申请、事务详情、管理员审核、场地时段、知识库与 AI 证据视图。
2. **领域层**：表单 Schema、规则引擎、状态机、版本与时间轴、校园时钟。
3. **Agent 层**：任务模板、最小上下文装配、模型适配、输出解析、证据校验、有限修复与降级。
4. **知识层**：场地规则、申请指南、设备说明与开放时间，按规则检索并返回带来源的片段。
5. **数据层**：D1/SQLite 保存场地、事务、版本、事件、规则、知识片段和 AI 运行。

## 信任边界

- 浏览器不接触模型密钥。
- **操作身份由服务端会话决定**。业务接口不接受请求体中的 `role`；`/api/case` 只认 HttpOnly Cookie 中的身份，因此申请人无法通过改写请求批准自己的申请。
- 用户文本、附件和知识片段均视为不可信数据，不进入系统指令区。
- 模型不能获得状态写入、任意数据库或发布正式通知的工具。
- 模型输出先通过 JSON Schema，再检查任务类型、规则 ID、证据 ID、数字、日期和枚举。
- 失败结果写入运行记录，但不得改变事务状态。

### 演示身份与生产化路径

`/api/demo/role` 是**仅供演示的身份切换入口**，让评委在同一个浏览器里分别以申请人和管理员走完闭环。它是这套设计唯一需要替换的接缝：生产环境删除该路由，由校园统一身份认证写入同一个会话，`lib/server/session.ts` 之后的状态机、权限判定与审计写入完全不变。

## 会话隔离

演示链接会被多位评委同时打开。每位访问者由 HttpOnly 会话 Cookie 派生出独立的案件编号（`CA-2026-0902-<会话前缀>`），互相看不到也改不动对方的事务；`重置演示` 只清除调用者自己的案件。场地、规则与知识库是全库共享的参考数据，按 `REFERENCE_DATA_VERSION` 版本号自动对齐，部署后无需手工重灌。

## 确定性规则集

| 规则 ID | 判定 | 知识依据 |
| --- | --- | --- |
| `VENUE-REQ-001` | 必填字段完整，并逐项列出缺项名称 | `KB-VENUE-001` |
| `VENUE-TIME-001` | 结束时间晚于开始时间 | `KB-VENUE-001` |
| `VENUE-CAP-001` | 人数为正整数且不超过场地容量 | `KB-VENUE-001` `KB-SAFETY-001` |
| `VENUE-SLOT-001` | 与已占用时段无重叠 | `KB-VENUE-001` |
| `VENUE-EQP-001` | 设备需求可被场地满足 | `KB-VENUE-002` |
| `VENUE-HOUR-001` | 在场地开放时间内且不跨日 | `KB-VENUE-003` |

规则表、Agent 输出白名单和知识检索共用 `lib/domain/rules.ts` 中的同一份 `ruleCatalog`，规则不可能只存在于其中一处。

## 时间处理

Worker 运行在 UTC，评委的机器可能在任何时区。所有规则判定与界面展示都通过 `lib/domain/time.ts` 固定在 `Asia/Shanghai` 墙钟上，避免同一条申请在不同机器上落到开放时间的两侧。

## 状态机

```text
draft → submitted → under_review → approved → completed
                              ↘ returned → draft (new version)
```

每次写操作都携带操作者、当前版本和幂等键。幂等键由服务端从 `(案件, 版本, 原状态, 目标状态)` 推导，重复点击或重试会命中同一把键并合并为一次事件。退回后修改必须生成新版本，旧版本不可覆盖。

## Agent 输出契约

发给模型的输出契约由 `z.toJSONSchema()` 从校验它的那份 Zod Schema 直接生成，因此"告诉模型的形状"和"校验时要求的形状"不可能不一致。

校验失败时最多再问一次，并把校验器的具体报错回传给模型；这一次修复只在真实模型模式、且没有注入故障时发生。每一次尝试都单独写入 `ai_runs`，被拦下的坏输出仍然留在证据面板里。

## 模型适配

- `mock`：固定且可测试的结构化响应，支持无网络演示。
- `live`：通过 OpenAI-compatible HTTP API 接入 DeepSeek 或其他 MaaS。
- 所有提供方共享相同任务和输出契约，模型更换不改变业务代码。

## 故障注入

演示用的三种故障独立于模型模式，真实模型下同样生效：

| 故障 | 注入方式 | 预期错误码 |
| --- | --- | --- |
| 非法 JSON | 真实调用后替换响应为自然语言 | `INVALID_JSON` |
| 虚构规则 | 把 `VENUE-RULE-999` 注入各任务 Schema 已声明的字段 | `RULE_NOT_FOUND` |
| 模型超时 | 收缩请求预算，真实中断连接 | `MODEL_TIMEOUT` |

超时故障收缩的是真实的请求预算而不是伪造耗时，所以证据面板里记录的延迟仍然是真实测量值。

## 部署

应用输出为 Cloudflare Worker 兼容的 ESM，结构化状态使用 D1。运行时密钥由托管环境变量注入，不进入 Git、浏览器包或日志。
